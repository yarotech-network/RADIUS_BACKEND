# Mandatory subscription payment gate

User decision: expired workspaces must not reach dashboards or perform application activity; public and agent sales stop. Authentication, subscription status, owner renewal/verification and logout remain accessible. Confirmed user decision: existing customers continue using their issued vouchers until their normal expiry. New storefront purchases stop, plans disappear, and renewal restores the catalogue.

Implemented: enforce the gate after JWT authentication for all normal API views, with a narrow route-name exception list; preserve provider callbacks and existing customer-access paths. Add a role-scoped subscription access endpoint. Recheck new public checkout against the destination tenant, and shared new voucher issuance against its tenant. Gate React before operational layouts mount; route to a standalone renewal page, fail closed on unknown status, poll renewal and expiry, and retain owner-only billing authority. Test real JWT requests, public purchase denial without provider calls, login/status/renewal recovery, and frontend no-dashboard rendering. No schema migration, live operation, or Wi-Fi disconnection.

Application contract: GET `/api/v1/subscriptions/access/` returns `required`, `can_renew`, `status`, and `expires_at` with private/no-store caching. Blocked operational JWT requests return HTTP 403 with `code: subscription_required`. The normal API uses the subscription-aware JWT authenticator so per-view permission overrides cannot bypass it. Login/bootstrap/logout and owner billing remain available. React checks access before mounting operational layouts and uses `/renew-subscription`, preserving callback query parameters. Status failures keep the dashboard closed.

Verification uses actual JWT authentication (not forced authentication) for expiry boundary tests, mocked payment providers, and disposable SQLite databases. PostgreSQL locking/concurrency, VPS deployment, real payment settlement, and router traffic remain unverified. No migration is added by this gate and no existing database migration was applied. Django administration remains restricted by its existing staff permissions and is not the tenant React application.

Local results (2026-09-14): 138 backend tests passed across subscriptions, payments, vouchers and agents; seven concurrency tests were excluded from the passing SQLite run because they require PostgreSQL. All 21 frontend subscription gate/login tests passed. TypeScript checking and the production build passed. No provider calls or production database changes were made.

Catalogue implementation plan: return an empty paginated public plan list while operator access is blocked, preserve the existing checkout rejection, prevent HTTP caching, and refresh open storefront catalogues periodically. Keep issued voucher and RADIUS lifecycle unchanged. Verify empty/renewed catalogue transitions and existing voucher records in isolated tests. No schema change.
