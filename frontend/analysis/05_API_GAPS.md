# 05 — Backend/API gaps that shape the frontend

These are things the UI would naturally want but the backend does **not** provide. The frontend will not fabricate them; each has a stated fallback. Items marked **(blocking-ish)** materially degrade a workflow and are worth a small backend follow-up.

| # | Gap | Evidence | Frontend handling |
|---|---|---|---|
| 1 | **Agents cannot list the plans they can buy.** `GET plans/` uses `tenant_for()` → agents (no membership/staff assignment) get 403. There is no `agent/plans/` endpoint and the agent login/profile payload contains no tenant slug. **(blocking-ish)** | `apps/vouchers/views.py::InternetPlanViewSet.get_queryset`, `apps/core/api.py::tenant_for`, `AgentProfileSerializer` (tenant is an id) | Agent "Sell" screen loads plans from the public catalogue `GET public/tenants/{slug}/plans/` **only if** a slug is known: the portal will accept `?tenant=<slug>` on the agent login URL / a "Your operator's storefront slug" field saved locally; otherwise it falls back to entering a plan ID manually with a clear message. Recommended backend fix: expose `tenant_slug` on `agents/me/` or add `GET agent/plans/`. |
| 2 | **Generated voucher passwords are not returned by `vouchers/generate/`, `POST vouchers/`, or agent `generate/`.** `password` is write-only; credentials are only visible through `vouchers/{id}/print/` and `/pdf/` (manager/staff), and agents have **no** print/pdf permission. **(blocking-ish for agents)** | `VoucherSerializer.extra_kwargs`, `AgentVoucherAllocationSerializer`, `VoucherViewSet.get_permissions` (print/pdf need `IsAuthenticated` but the queryset is `tenant_for()` → 403 for agents) | Workspace: after generation, offer per-voucher "Print" (fetches HTML) and "Print all" (sequential fetches into one print document). Agent portal: show usernames and explain that credentials are printed by the operator; surface this gap prominently in docs. Recommended fix: return `password` in the generate responses (they are creation responses) or add an agent-scoped print endpoint. |
| 3 | **No user directory / user search.** Team membership creation and staff-assignment creation require an existing **numeric user id**; there is no `GET users/`. | `TenantMembershipSerializer.user` is a PK field; no users endpoint in `openapi-v1.yaml` | Team → "Add member" asks for the user's ID with helper text ("Ask the user for the ID shown on their Profile page"). The Profile page displays the user's ID with a copy button. |
| 4 | **No invitation e-mail for staff invitations**; the token is returned once at creation. | `StaffInvitationViewSet.create` | Console shows a one-time "Copy invitation link" (`/accept-invitation?token=…`) with a warning that it cannot be retrieved later. |
| 5 | **Commission is never computed** (`commission_earned` stays 0; `agent_commission_percent` is unused by business logic). | `AgentService.generate_voucher_from_wallet` sets no commission; grep shows no writer | Agent stats show "Commission this month" only when >0; otherwise the card is omitted. Settings label the commission % as "recorded for reporting; not applied automatically". |
| 6 | **No time-series / trend data** (revenue by day, sessions over time, voucher usage). Only totals. | `DashboardStatsView`, `PlatformStatsView` | No charts. Dashboard uses stat cards + "needs attention" list + activity feed. |
| 7 | **No router telemetry**: `health.online` is always `null`, `telemetry_available:false`; `last_seen_at` only changes if `refresh_router_statuses` runs. | `RouterOperationActions.health` | Router health card shows "Telemetry not available"; `last_seen_at` shown as "Last seen (ping worker)" with staleness. Never shows Online/Offline. |
| 8 | **Live sessions lack client IP / MAC** (`client_ip` always null) and there is **no usage/accounting history** endpoint (closed sessions, per-voucher usage). | `LiveUsersView` | Sessions screen shows only live sessions; voucher detail has no usage tab. |
| 9 | **Paystack return URL is not passed by the backend** (`callback_url` absent). Where the browser lands after payment depends on the Paystack dashboard configuration. | `PaystackService.initialize_transaction` | The frontend provides three return pages (`/pay/result`, `/agent/wallet/return`, `/settings/subscription`) that poll by `reference`; docs instruct the operator to configure Paystack's callback URL to `/pay/result` (Paystack appends `?reference=`). Agent/subscription flows also store the reference locally before redirecting so the return page can recover it. |
| 10 | **Public purchase result never exposes credentials**; `payments/callback/` returns only the voucher username, and credential e-mail delivery is a manual operator command (`deliver/`). | `PaymentCallbackView`, `PaymentRecoveryViewSet.deliver` | Public result page shows status + username and a message that login details are sent by the operator; workspace Recovery board makes "Deliver" the obvious next action for `fulfilled` + `not_requested`. |
| 11 | **No public voucher self-check / resend**, no customer accounts. | report: "No public resend/recovery endpoint" | Not built. |
| 12 | **Subscription plans have no write API** and no trial auto-creation; subscription status is not enforced. | `SubscriptionPlanViewSet` read-only; no `TenantSubscription` creation outside payments | Console shows pricing read-only; workspace Subscription page shows "No subscription yet" (404) and checkout for owners. No feature gating implemented on the client. |
| 13 | **Agent credit accounts / ledgers have no API.** | `AgentCreditAccount`, `AgentCreditLedger` unused by views | Not surfaced. |
| 14 | **WhatsApp**: only credential storage exists (no messages, orders, or route-link endpoint; `generate_route_url` is service-only). `WhatsAppSenderBinding` has no API. | `whatsapp_routing/views.py` | Settings → Integrations shows a single "WhatsApp route" form. No chat/orders UI. |
| 15 | **MAC devices are a registry only** — no RADIUS MAC-auth wiring or usage. | grep: `MacDevice` unused outside its app | Devices screen is a CRUD registry with plan + expiry; copy avoids implying network enforcement. |
| 16 | **Voucher batch identity is not stored** (no `batch_id`); the only batch trace is the audit event `vouchers.generated` with `quantity`/`plan_id`. | `VoucherViewSet.generate` | Generate result sheet holds the batch in memory for print; Vouchers list offers `created_after/created_before` filters to approximate a batch. |
| 17 | **No bulk voucher operations** (bulk disable, bulk PDF). | endpoints are per-id | Bulk print is implemented client-side by fetching each `print/` page sequentially (bounded by the ≤100 batch size). No bulk disable. |
| 18 | **`PATCH tenant/agents/{id}` cannot change username/email/password**; agent password resets go through the normal `auth/password-reset/` e-mail flow. | `AgentEditSerializer` | Agent detail shows this hint under "Login details". |
| 19 | **Live sessions `router` filter accepts a router UUID only**; no filter by voucher plan. | `LiveUsersView` | Router select only. |
| 20 | **Audit `actor` is a user id** with no name; there is no user lookup. | `AuditSerializer` | Shows "User #id" (and "You" when it matches the current user). |
| 21 | Agent login returns `agent{}` not `user{}`; role detection needs a follow-up `GET auth/user/`. | `AgentLoginView` | Bootstrap always calls `auth/user/` after any login. |
| 22 | Platform admin cannot access tenant-scoped data (vouchers, plans, sessions) of a tenant without a membership; only the `platform/*` read models. | `tenant_for()` raises for admins without membership | Console tenant detail links to `platform/routers?tenant=`, `platform/payments?tenant=`, memberships; no "impersonate" feature. |
| 23 | **Platform staff cannot resolve tenant names.** `GET staff/assignments/` returns tenant *ids*; `GET tenants/` for a staff user returns an empty page (queryset is membership-based), and `public/tenants/{slug}/` needs a slug. *(Confirmed against the running API during Phase 3.)* | `MyStaffAssignmentsViewSet`, `TenantViewSet.get_queryset` | Tenant picker / switcher show **“Tenant #id”**; the workspace header shows the same label. Recommended fix: add `tenant_name` (and `tenant_slug`) to `StaffAssignmentSerializer`. |

Non-gaps worth stating (so nobody "fixes" them client-side): amounts are kobo; vouchers can only be disabled once issued; router secrets are unreadable by design; ambiguous NAS addresses are excluded from sessions by design.
