## How I will verify against the real API

The sandbox can install Python packages; Postgres is not available, so I will run the backend locally on **SQLite with a test-only settings override** (the unmanaged FreeRADIUS tables are created manually) purely to exercise real request/response shapes, auth flows, throttles, idempotency headers and error envelopes. This is a verification harness only — the target deployment remains PostgreSQL + FreeRADIUS as documented by the backend team. Anything that depends on Paystack, SSH/WireGuard, SMTP or a live RADIUS server is exercised only up to the backend's documented failure responses (503/409), which the UI must handle anyway.

## Repository hand-off

The frontend lives in a **new repository**. During this session the code is produced under `frontend/` in this checkout so it is tracked by the session branch; the folder is self-contained (own `package.json`, no imports from the Django tree) and can be moved verbatim to `yarotech-radius-frontend` (`git subtree split --prefix frontend` or copy) at the end.
